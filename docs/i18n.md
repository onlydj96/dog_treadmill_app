# 다국어 (한국어 · English)

앱(실제 앱·데모 앱)의 모든 화면 문구를 한국어와 영어로 제공한다. 기본은 한국어이고,
**마이페이지 › 설정 › 언어 (Language)** 또는 **로그인 화면 오른쪽 위 언어 버튼**에서 English로 바꾼다.
선택한 언어는 기기에 저장된다(`SharedPreferences` 키 `app_language`, 로그인과 무관).

## 구조

| 파일 | 역할 |
|---|---|
| `l10n.yaml` | `flutter gen-l10n` 설정 (템플릿은 한국어 ARB) |
| `lib/l10n/app_ko.arb` | 한국어 문구 (템플릿: 자리표시자 메타데이터 `@key`는 여기에만 쓴다) |
| `lib/l10n/app_en.arb` | 영어 문구 |
| `lib/l10n/generated/` | 생성 코드 (`flutter gen-l10n`, `flutter pub get` 때 다시 만든다. 직접 고치지 않는다) |
| `lib/l10n/l10n.dart` | `context.l10n`, 위젯 밖에서 쓰는 `L10n.current` · `L10n.pick`, `AppLanguage` |
| `lib/l10n/app_language.dart` | 언어 설정 Provider(`appLanguageProvider`), 언어 선택 시트, 언어 버튼 |
| `lib/l10n/server_text.dart` | 서버가 저장하는 기본 한국어 문구를 현재 언어로 바꾸는 도우미 |
| `lib/core/utils/formatters.dart` | 날짜·금액·시간 포맷(`Fmt`)과 조사 도우미(`particle`). 현재 언어를 따른다 |

언어를 바꾸면 `L10n.use()`로 위젯 밖 문구를 먼저 바꾸고, `MaterialApp.locale`이 바뀌면서
`RebuildOnLocaleChange`(lib/app.dart)가 화면 전체를 한 번 다시 그린다.

## 문구 추가 규칙

1. 화면에 보이는 문구는 코드에 직접 쓰지 않고 두 ARB 파일에 같은 키로 넣는다. 그 뒤 `flutter gen-l10n`.
2. 위젯에서는 `context.l10n.키`, 위젯 밖(모델·enum·Provider·목업 서버)에서는 `L10n.current.키`.
3. 값이 들어가는 문구는 문자열을 이어 붙이지 말고 자리표시자를 쓴다 (언어마다 어순이 다르다).
   ```json
   // app_ko.arb
   "bookingDogTime": "{dog} · {time} 예약",
   "@bookingDogTime": {"placeholders": {"dog": {"type": "String"}, "time": {"type": "String"}}},
   // app_en.arb
   "bookingDogTime": "Booking for {dog} · {time}",
   ```
4. 영어에서 개수에 따라 단어가 바뀌면 ICU 복수형을 쓴다. 한국어는 그대로 둔다.
   `"dogCount": "{count, plural, =1{1 dog} other{{count} dogs}}"` (자리표시자 타입은 `int`)
5. 이름 뒤 조사(와/과, 을/를, 이/가)는 ARB가 계산할 수 없으므로 `particle(이름, '와', '과')`로 만든 값을 넘긴다.
   한국어에서는 조사가 붙고("콩이와"), 영어에서는 이름만 들어간다("Kongi").
6. 날짜·시간·금액·거리·점수는 항상 `Fmt`를 쓴다 (단위를 직접 쓰지 않는다).
7. enum 라벨은 이름(`label`)을 그대로 두고 getter로 바꾼다.
   ```dart
   enum DogSex {
     male('male'),
     female('female');

     const DogSex(this.dbValue);
     final String dbValue;

     String get label => switch (this) {
           DogSex.male => L10n.current.dogSexMale,
           DogSex.female => L10n.current.dogSexFemale,
         };
   }
   ```
8. 주석, `assert`·`UnimplementedError`처럼 개발자만 보는 메시지는 번역하지 않는다.
9. `confirmDialog`의 버튼 이름을 주지 않으면 "확인"/"취소"(현재 언어)가 들어간다.

### 키 이름

lowerCamelCase로, 기능 영역 접두어를 붙인다. 같은 뜻이라도 화면마다 쓰임이 다르면 키를 따로 둔다.

| 접두어 | 영역 |
|---|---|
| `common` `nav` `language` `fmt` `validation` `error` `server` `video` `config` | 공통 (lib/core, lib/l10n) |
| `auth` `signup` | 로그인 · 회원가입 |
| `consent` | 동의 관리 |
| `myPage` `profileEdit` `notificationSettings` | 마이페이지 |
| `notification` | 알림함 · 알림 문구 |
| `support` `notice` `faq` `inquiry` | 공지 · FAQ · 1:1 문의 |
| `home` | 홈 |
| `booking` | 예약 |
| `membership` `payment` | 이용권 · 결제 |
| `dog` | 반려견 (견종 · 건강 정보 포함) |
| `exercise` | 운동 |
| `health` `analysis` `keypoint` | 건강 · AI 분석 |

| `demo` | 데모 앱 전용 |

## 서버에서 오는 텍스트

DB 행·RPC 결과·AI 결과처럼 서버가 주는 사람이 읽는 텍스트는, 영어 값을 **같은 이름 + `_en`** 으로 함께 둔다.
앱은 영어 화면에서 `_en` 값이 비어 있지 않으면 그것을, 아니면 기본(한국어) 값을 보여 준다: `L10n.pick(ko, en)`.
모델은 기존 공개 이름(예: `Branch.name`)이 현재 언어의 값을 돌려주게 해서 화면 코드를 바꾸지 않는다.

### DB 컬럼 (supabase/migrations/20261117000100_english_content.sql)

| 테이블 | 영어 컬럼 |
|---|---|
| `branches` | `name_en`, `address_en` |
| `exercise_programs` | `name_en`, `description_en` |
| `membership_plans` | `name_en`, `description_en` |
| `notices` | `title_en`, `body_en` |
| `faqs` | `category_en`, `question_en`, `answer_en` |
| `breeds` | `name_en` |
| `health_conditions` | `name_en`, `description_en` |
| `badges` | `name_en`, `description_en` |
| `analysis_reports` | `summary_en` (text), `care_notes_en` (jsonb 문자열 배열) |

- 운영자가 새 지점·상품·공지·FAQ를 넣을 때 영어 컬럼도 채운다. 비워 두면 영어 화면에서도 한국어가 보인다.
- 구매 시점에 복사해 두는 값(`memberships.plan_name`)은 상품 영어 이름을 함께 읽어 고른다:
  `select('*, plan:membership_plans(name_en)')` → `plan: {name_en}` (상품이 지워졌으면 null).
- `dogs.breed`는 카탈로그 견종이면 카탈로그 한국어 이름이다. 영어 이름은 함께 읽는다:
  `select('*, breed_catalog:breeds(name_en)')` → `breed_catalog: {name_en}` (카탈로그 견종이 아니면 null).
  예약에 붙는 반려견(`dog:dogs(...)`)도 같은 별칭을 쓴다. 데모 목업 서버도 같은 모양으로 돌려준다.
  믹스견에 보호자가 직접 적은 견종은 입력한 그대로 보여 준다.
- AI 결과 JSON(`joint_metrics`, `anomaly_metrics`)의 문구도 같은 규칙: `label_en`, `description_en`, `notes_en`.
  관절 라벨은 `label_en`이 없으면 앱의 관절 이름(`DogKeypoint.label`, 현재 언어)을 쓴다.

### RPC 결과

표시용 문구 필드마다 `_en` 필드를 함께 돌려준다.

| 함수 | 영어 필드 |
|---|---|
| `get_leaderboard` | `breed_label_en`, `main_branch_name_en`, `title_label_en` |
| `get_my_ranking` | 범위별 `label_en` |
| `get_branch_battle` | `branch_name_en` |
| `get_ranking_dog_profile` | `breed_label_en`, 수상 기록의 `scope_label_en`, 배지의 `name_en`·`description_en` |
| `get_dog_achievements` | 수상 기록의 `scope_label_en`, 배지의 `name_en`·`description_en` |
| `get_hall_of_fame` | `scope_label_en`, `breed_label_en` |

영어 라벨 규칙: 전체 `Overall`, 체급 `Small dogs`·`Medium dogs`·`Large dogs`, 지점은 `branches.name_en`,
견종은 `breeds.name_en`, 믹스견 `Mixed breed` / `Mixed (Maltipoo)`.

### 알림 (notifications.data)

DB 트리거가 만드는 알림은 기존 한국어 `title`/`body`와 함께 `data.msg`(문구 종류)와 `data.args`(값)를 저장한다.
앱은 아는 `msg`면 현재 언어로 문구를 만들고, 모르는 `msg`이거나 없으면(이전 알림) `title`/`body`를 그대로 보여 준다.
언어를 바꾸면 지난 알림도 새 언어로 보인다.

| `msg` | 한국어 제목 · 본문 (DB와 같은 문구) | `args` |
|---|---|---|
| `booking_confirmed` | 예약이 확정되었어요 · `{dog} · {when} 예약이 확정되었습니다.` | `dog_name`, `start_at` |
| `booking_cancelled` | 예약이 취소되었어요 · `{dog} · {when} 예약이 헬스장 사정으로 취소되었습니다.` | `dog_name`, `start_at` |
| `booking_no_show` | 미방문 처리되었어요 · `{dog} · {when} 예약이 미방문으로 처리되었습니다.` | `dog_name`, `start_at` |
| `exercise_started` | 운동을 시작했어요 · `{dog}의 트레드밀 운동이 시작되었습니다. 실시간 현황을 확인해 보세요.` | `dog_name` |
| `exercise_completed` | 운동을 완료했어요 · `{dog}의 운동이 끝났어요. ({points}점을 받았어요! )운동 기록을 확인해 보세요.` | `dog_name`, `points` (0이면 점수 문장 없음) |
| `exercise_stopped` | 운동이 중단되었어요 · `{dog}의 운동이 중단되었습니다. 사유: {reason}` | `dog_name`, `reason` (null이면 `-`) |
| `analysis_completed` | AI 보행 분석 리포트가 도착했어요 · `{dog}의 운동 분석 결과를 확인해 보세요.` | `dog_name` |
| `analysis_failed` | AI 분석을 완료하지 못했어요 · `{dog}의 영상 분석 중 문제가 발생했습니다. 헬스장에서 확인 후 다시 분석합니다.` | `dog_name` |
| `badge_earned` | 새 배지를 받았어요 · `{dog}의 「{badge}」 배지가 도착했어요. 배지함에서 확인해 보세요.` | `dog_name`, `badge_code`, `badge_name`, `badge_name_en` |
| `cheer_received` | 응원이 도착했어요 · `{nickname}님이 {dog}를 응원했어요.` (닉네임 없으면 `다른 보호자가`) | `dog_name`, `nickname` (null 가능) |
| `monthly_award` | `{month}월 랭킹 시상대에 올랐어요` · `{dog}가 {month}월 랭킹 {summary}에 올랐어요. 명예의 전당에서 확인해 보세요.` | `dog_name`, `month` (1~12), `awards`: `[{scope, label, label_en, rank}]` |

- `start_at`은 ISO 8601 시각이다. 앱은 `Fmt.dateTime`(기기 시간대)으로 보여 준다.
- `summary`는 수상 목록을 언어별로 만든다. 한국어 `전체 1위 · 용산 아이파크몰점 2위`, 영어 `#1 Overall · #2 Yongsan I'Park Mall`.
- 운동 중단 사유가 DB 기본값('운영자 판단에 의한 중단')이면 `localizedStopReason`이 현재 언어로 바꾼다.

### 가입 닉네임

앱은 회원가입 때 사용자 메타데이터에 `locale`(`ko`/`en`)을 함께 보낸다. 가입 트리거는 `en`이면 영어 닉네임을,
아니면 지금처럼 한국어 닉네임을 자동으로 만든다.

## 데모 앱

데모 앱은 실제 앱과 같은 화면을 쓰므로 화면 문구는 위 규칙 그대로 바뀐다. 목업 서버(lib/demo/mock_server)는

- 실제 DB와 같은 영어 컬럼·RPC 필드·알림 `msg`/`args`를 똑같이 돌려준다.
- 샘플 데이터 중 실제로는 사용자가 입력하는 값(반려견 이름, 다른 보호자의 닉네임, 문의 내용 등)은
  데모 전용 키 `<키>__en`(밑줄 두 개)에 영어 값을 함께 둔다. 데모 저장소가 화면에 넘기기 전에 현재 언어 값으로 바꾼다.
- 데모 저장소 Provider가 언어 설정에 의존하므로, 언어를 바꾸면 화면이 데이터를 다시 불러와 샘플 데이터까지 바뀐다.
- 데모 컨트롤 패널에서도 언어를 바꿀 수 있다.

## 테스트

- `test/helpers/l10n.dart`
  - `initTestLocales()`: 두 언어의 날짜 기호 준비 (`setUpAll`)
  - `localizedApp(home, language: AppLanguage.en)`: 앱과 같은 다국어 설정의 `MaterialApp`
  - `useLanguage(AppLanguage.en)`: 위젯 밖 문구(포맷터·라벨·오류)를 이 테스트 동안 영어로 (끝나면 한국어)
  - `languageOverride()`: SharedPreferences 없이 언어 설정 Provider를 쓰는 화면용
- 기존 테스트는 한국어 화면을 기준으로 한다. 한국어 문구를 바꾸지 않으면 그대로 통과한다.
